# Кейс-задача №4. Книжный магазин

> Учебное **web-приложение книжного магазина** с пользовательским и административным интерфейсами, электронной библиотекой, системой сортировки, покупкой и арендой книг.

Приложение предоставляет пользователям возможность просматривать каталог книг, сортировать их по **категории, автору и году написания**, а также приобретать или арендовать книги на срок **2 недели, 1 месяц или 3 месяца**.

Администратор может управлять каталогом, изменять цены и статусы книг, контролировать их доступность, а также отслеживать сроки аренды пользователей.

> **Примечание:** в данном README подробно представлен реализованный функционал приложения с наглядными примерами его работы.

# Запуск проекта

Для запуска приложения необходимо выполнить следующие шаги:

1. Создать базу данных с названием `book_store`.
2. Импортировать структуру и исходные данные из файла `bd.sql`.
3. Запустить приложение.
4. Авторизоваться с помощью тестового аккаунта или зарегистрировать нового пользователя.

Администратор может:

* добавлять новые книги;

* удалять книги;
* изменять цены;
* изменять статус книг;
* управлять доступностью книг;
* контролировать сроки аренды пользователей.

#  Итог и Анализ выполненной задачи
В результате выполнения кейс-задачи была разработана **web-версия книжного магазина** с разделением функциональности между пользователем и администратором.

1. Создана полноценная web-версия книжного магазина на PHP и MySQL. Каталог показывает книги, цену, автора, категорию, год, описание, обложку и доступность.

2. Реализованы два интерфейса. Пользователь работает с каталогом, корзиной и личной библиотекой. Администратор получает отдельную панель управления каталогом и пользователями.

3. Используется обычная реляционная MySQL БД. Основные таблицы: `users`, `books`, `purchases`, `rentals`, `cart_items`. Связи реализованы внешними ключами InnoDB.

4. Для книги хранятся два пути: `image_path` для изображения обложки и `file_path` для электронного файла. Это позволяет хранить сами файлы отдельно от базы данных.

5. Реализована сортировка и фильтрация каталога. Можно выбрать категорию, автора, год и вариант сортировки.

6. Реализована учебная покупка. Реальных платежей нет: стоимость списывается с поля `balance` пользователя. После покупки книга фиксируется в таблице `purchases`, а её статус становится `sold`.

7. Реализована аренда на 14, 30 или 90 дней. При оформлении деньги списываются с баланса, создаётся запись в `rentals`, а книга переводится в статус `rented`.

8. Добавлена корзина. В ней можно собрать несколько книг, переключить для каждой книги покупку или аренду и выбрать срок аренды. После оформления используется одна транзакция.

9. Реализовано скачивание файлов. Скачивать купленные книги может только их покупатель. Для аренды файл доступен только во время активного срока. Путь проверяется так, чтобы нельзя было выйти за пределы директории файлов.

10. Автоматическое окончание аренды выполняется при обращении к приложению. Просроченные аренды становятся `expired`, а книги возвращаются в статус `available`. В админ-панели выводятся аренды, которые заканчиваются в ближайшие три дня, что выполняет требование об автоматическом напоминании в учебном формате.

11. Администратор может добавлять, изменять и удалять книги, менять цену, описание, статус, путь изображения и путь электронного файла. Т

12. Интерфейс оформлен современно и адаптивно: используются CSS Grid и Flexbox, тёмная цветовая схема, отдельная страница книги, карточки каталога и блоки корзины.

13. Пароли хранятся в виде хешей `password_hash`, а параметры запросов передаются через подготовленные PDO-запросы. В `download.php` дополнительно ограничен путь доступным каталогом файлов.

## Выявленные ошибки и рекомендации

1. Реальной оплаты нет. Это подходит для учебного проекта, но для реального магазина потребуется платёжный провайдер.

2. Автоматическое напоминание сейчас лишь на сайте. Для реального уведомления нужен cron и отправка email/уведомлений пользователям.

3. Для всех POST-форм стоит добавить CSRF-токены перед публикацией проекта в интернете.

4. Загрузка файлов пока делается указанием пути в админ-панели. Улучшение — добавить безопасную загрузку файлов с проверкой MIME-типа, размера и расширения.

5. Для большого каталога нужна пагинация и поиск по названию.

6. Для магазина с несколькими экземплярами одной книги стоит хранить количество экземпляров отдельно, а не менять статус всей книги.

7. Баланс учебный. Для реальной системы стоит хранить историю операций по балансу и запретить ручное изменение денежных данных без журнала операций.

8. Следующим улучшением можно сделать полноценную страницу заказа с историей покупок, возвратов и сроков аренды.
